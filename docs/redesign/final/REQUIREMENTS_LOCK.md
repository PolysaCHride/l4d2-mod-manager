## 二、技术路线修正（关键）

你选了 B（PySide6 + WebEngine），但**按我上一轮的写法做不进 100MB**。实测：

| 组件 | 体积 |
|---|---:|
| `Qt6WebEngineCore.dll` | **193 MB** |
| `resources/`（含 78MB debug pak + 10MB icudtl） | **106 MB** |
| `qtwebengine_locales`（53 个语言） | 41 MB |
| Core + Gui + Widgets | 25 MB |

**光核心 DLL 就是预算的两倍。** 即使裁掉 debug 资源、只留中文 locale，仍然 250 MB 以上。B 方案按 QtWebEngine 实现，物理上不可能。

### 替代：pywebview + 系统 WebView2

同样的 HTML/CSS/JS 前端，换一个承载层：

| 项 | 数据 |
|---|---:|
| pywebview 包（解包后） | **1.6 MB** |
| 系统 WebView2 Runtime | 已装（388 MB，**不占你的分发体积**） |
| 本机 WebView2 版本 | 157.0.4341.60 |

**体积账**（估算，需实测）：

```
Python 运行时 + 标准库     ~15 MB
PySide6 Core/Gui/Widgets   ~25 MB   ← 仍需 Qt 做窗口、线程、文件对话框
pywebview                  ~1.6 MB
业务逻辑 + 资源            ~5 MB
────────────────────────────────
合计                        ~47 MB
```

**远低于 100 MB。** 且前端代码 100% 复用，与 QtWebEngine 方案的设计产物完全一致。

### 代价（必须提前知道）

| 风险 | 说明 | 缓解 |
|---|---|---|
| 依赖系统 WebView2 | Windows 10/11 已内置；Win7/部分精简系统没有 | 启动时检测，缺失则弹窗给下载链接 |
| 窗口控制 | pywebview 的 API 比 Qt 简单，无边框/自定义标题栏需要额外处理 | 用 `frameless=True` + JS 调用窗口 API |
| 双栈调试 | 问题可能在 Python、JS 或两者之间 | 统一 stderr 日志前缀 |
| 中文输入法 | WebView2 用的是 Edge，通常无问题 | 第一步实测 |

**如果第一步实测体积或输入法不达标，回退到「纯 PySide6 原生」（A 方案）**，代价是前端重写，但业务逻辑不动。
