## 相比原方案增加的显眼度

你提的「避免失去焦点时注意不到」，落在四个地方：

1. **背景衬底**：活跃态整块有 `#161c0e` 深色胶囊底，和周围区分开。
2. **呼吸圆点**：`status-pulse` 1.4s 循环，透明度 1 → 0.35。
3. **进度条**：104×4px，酸绿填充，`transition: width .2s linear` 平滑推进。
4. **字号提升**：活跃态文字 9.5px，比空闲态的 8.5px 大一号，颜色也从灰绿提到 `#e2ecc8`。

## 异常态（未画进预览，实现时补）

| 情况 | 表现 |
|---|---|
| 游戏目录缺失 | 整条左侧变 `--danger`：`未找到游戏目录 · 去设置`，点击跳设置 |
| 扫描失败 | `--danger`：`扫描失败 · 重试` |
| 游戏运行中 + 需要写入 | `--warning`：`游戏运行中，写入已锁定` |

这三种都是**需要用户行动**的状态，所以用颜色和可点击文案，而不是灰色提示文字。

## 实现要点（落到 Qt 时）

- `QStatusBar` 换成自绘的 28px widget，左侧一个 `QLabel` 承载「点 + 文字」，进度用 `QProgressBar`（fixedSize 104×4）。
- 状态切换用一个枚举：`IDLE / SCANNING / IMPORTING / DOWNLOADING / ERROR / LOCKED`，避免各处零散 setText。
- 进度推进复用现有的 `ScanWorker` 进度信号，不新增数据源。
- 路径点击复用现有 `reveal_mod` 同级的目录打开逻辑。

2. **活跃态范围**：只在扫描时出现。导入、下载各有自己的进度条，不占用状态栏。

## 状态枚举（定稿）

| 状态 | 触发 | 左侧表现 |
|---|---|---|
| `IDLE` | 空闲 | 绿点 + `就绪` |
| `SCANNING` | 扫描 addons / workshop | 胶囊 + 呼吸点 + `扫描中 44/128` + 进度条 |

导入 / 下载**不进入**这个状态机，它们用自己的进度条：
- 导入：`06` 导入视图内的任务面板
- 下载：`06` 下载视图内的进度面板
