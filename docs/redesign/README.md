## 五版概览

| # | 方向 | 一句话 | 更适合 |
|---|---|---|---|
| 01 | **BLACKSITE / 战术档案** | 把现有末世军械库做成一台真正的本地 mod 控制台。 | 长期用户、高密度管理 |
| 02 | **SAFEHOUSE / 安全屋** | 像翻一本模组档案册，而不是打开一台机器。 | 轻度收藏用户、希望产品更有人味 |
| 03 | **WORKSHOP / 工坊中枢** | Steam 用户零学习成本的入口，下载与同步成为主角。 | 工坊重度用户、下载为主 |
| 04 | **LOADOUT LAB / 配装台** | 从「管理模组」升级为「管理今晚怎么玩」。 | 高频切换玩法、愿意升级产品概念 |
| 05 | **INDEX / 索引** | 给 100+ 模组库的一张工作台。 | 收藏很多、重整理与清理 |

## 这轮看到的现状问题

- 三级导航（一级分类 / 物品 / 卡片）并排，横向空间被切碎，主卡片只能做小。
- 启用状态依赖绿点与细勾选，不足以支撑「一键切换」这个核心动作。
- 搜索、排序、刷新、导入、工坊、启动挤在同一行，主次不分。
- 同组互斥的结果藏在状态栏或操作后提示里，无法在操作前预判影响范围。

## 我的建议

**首选 01 BLACKSITE。** 它最像这条产品线本来应该长成的样子：保留末世与军械库的气质，同时把可读性、层级、详情和冲突都拉回工作流。对现有用户的迁移成本最低，也最适合继续叠加工坊、下载和合集。

- 如果「快速上手」和工坊下载比品牌气质更重要：选 **03 WORKSHOP**。
- 如果模组量会很快到 300+：**05 INDEX** 的索引能力值得优先，甚至可以成为主结构。
- 如果愿意增加配装 / 预设数据模型：**04 LOADOUT LAB** 能把互斥规则变成真正的卖点。
- 如果想要完全跳出「游戏工具」的气质：**02 SAFEHOUSE** 差异最大，但也要接受浅色与纸感的代价。

## 需要你拍板

1. **气质**：末日军械库的控制台，还是更像日常软件的档案册 / 工具？
2. **规模**：模组量会到 300+ 吗？如果会，V5 的表格与批量操作应该成为主结构。
3. **路线**：要不要把「配装 / 预设」提上路线？这会决定 V4 是否值得进入下一阶段。

## 边界与说明

- 当前前端是 **PySide6 + QSS**；这些 HTML 原型是评审载体，**不意味着要直接换技术栈**。
- 样稿只覆盖主界面。设置、详情、下载、压缩包导入、迁移、空态、错误态在方向确定后补齐。
- 数据为示意内容；缩略图裁自当前版本截图，仅用于视觉评审。
- 颜色、字号、间距在各页 CSS 中已是可提取的 token；方向确定后再整理成统一设计系统。
- 主界面按 1440 × 900 设计；1100 宽已有折叠规则，但最终还要做一次完整的小窗口检查。

## 下一步

1. 确认主方案与要保留的局部（例如「01 的骨架 + 05 的表格」）。
2. 补齐所有状态页面，定义组件、间距、字体、控件状态与快捷键。
3. 用真实复杂度比较 PySide6 原生重绘、QWebEngine、Tauri；再给技术实现方案。
4. 业务逻辑不动，先换壳、再拆组件、最后处理动效与响应式。
